## Objectif

Écrire du code **réutilisable pour plusieurs types sans sacrifier la sécurité du typage**. Les génériques sont la troisième forme de polymorphisme vue dans la fiche [7. Polymorphisme](<../Partie II — Les 4 piliers de la POO/7. Polymorphisme.md>) : le *polymorphisme paramétrique*.

---

## Le problème : sans génériques

Avant les génériques (C# 1), les collections stockaient des `object`. On pouvait y mettre n’importe quoi… et le payer à l’exécution :

```csharp
ArrayList sansGenerique = new ArrayList { 1, "deux" };   // le compilateur accepte tout

int total = 0;
foreach (object o in sansGenerique)
    total += (int)o;   // 💥 InvalidCastException à l’exécution sur "deux"
```

Avec `List<int>`, l’erreur est détectée **à la compilation** : `new List<int> { 1, "deux" }` ne compile pas. C’est tout l’intérêt des génériques : le type est un **paramètre**, vérifié par le compilateur.

---

## Une classe générique

Le paramètre de type s’écrit entre chevrons, par convention `T` ou un nom préfixé par `T` :

```csharp
public class Paire<T1, T2>
{
    public T1 Premier { get; }
    public T2 Second { get; }

    public Paire(T1 premier, T2 second)
    {
        Premier = premier;
        Second = second;
    }

    public override string ToString() => $"({Premier}, {Second})";
}
```

```csharp
var p = new Paire<string, int>("Arthur", 42);
Console.WriteLine(p);              // (Arthur, 42)
Console.WriteLine(p.Second + 1);   // 43 : Second est bien un int, aucune conversion
```

---

## Une méthode générique

Une méthode peut avoir ses propres paramètres de type, même dans une classe non générique. Le compilateur les **déduit** le plus souvent des arguments :

```csharp
public static void Echanger<T>(ref T a, ref T b)
{
    T temporaire = a;
    a = b;
    b = temporaire;
}

int x = 1, y = 2;
Echanger(ref x, ref y);            // T est déduit : int
Console.WriteLine($"x = {x}, y = {y}");   // x = 2, y = 1
```

## Les contraintes `where`

Sans contrainte, le compilateur ne sait rien de `T` : on ne peut appeler que les méthodes d’`object`. Une **contrainte** garantit que `T` possède certaines capacités :

```csharp
public static T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;   // CompareTo est disponible grâce à la contrainte
```

| Contrainte | Signification |
| --- | --- |
| `where T : class` | `T` est un type référence. |
| `where T : struct` | `T` est un type valeur non nullable. |
| `where T : new()` | `T` possède un constructeur public sans paramètre. |
| `where T : Ennemi` | `T` est `Ennemi` ou une classe dérivée. |
| `where T : IComparable<T>` | `T` implémente l’interface indiquée. |
| `where T : notnull` | `T` n’est pas un type nullable. |

Les contraintes se combinent : `where T : Ennemi, IDamageable, new()`.

### Exemple : un inventaire typé

```csharp
public interface IObjet
{
    string Nom { get; }
    int Poids { get; }
}

public class Arme : IObjet
{
    public string Nom { get; init; }
    public int Poids { get; init; }
    public int Degats { get; init; }
}

public class Inventaire<T> where T : IObjet
{
    private readonly List<T> objets = new();
    private readonly int poidsMax;

    public Inventaire(int poidsMax) => this.poidsMax = poidsMax;

    public int PoidsTotal => objets.Sum(o => o.Poids);   // Poids est connu grâce à la contrainte

    public bool Ajouter(T objet)
    {
        if (PoidsTotal + objet.Poids > poidsMax)
            return false;

        objets.Add(objet);
        return true;
    }

    public IReadOnlyList<T> Objets => objets;
}
```

```csharp
var sac = new Inventaire<Arme>(poidsMax: 10);
Console.WriteLine(sac.Ajouter(new Arme { Nom = "Épée", Poids = 6, Degats = 12 }));  // True
Console.WriteLine(sac.Ajouter(new Arme { Nom = "Hache", Poids = 7, Degats = 15 })); // False : trop lourd
Console.WriteLine($"Dégâts de la première arme : {sac.Objets[0].Degats}");          // 12
```

`sac.Objets[0]` est directement une `Arme` : on accède à `Degats` sans aucune conversion.

## Variance : `List<Gobelin>` n’est pas une `List<Ennemi>`

Même si `Gobelin` hérite d’`Ennemi`, une `List<Gobelin>` **n’est pas** une `List<Ennemi>`. Sinon, on pourrait écrire :

```csharp
List<Ennemi> ennemis = new List<Gobelin>();   // ❌ ne compile pas…
ennemis.Add(new Dragon());                     // …car on pourrait glisser un Dragon parmi des Gobelins
```

En revanche, une interface qui ne fait que **produire** des valeurs, comme `IEnumerable<out T>`, est **covariante** : on ne peut rien y ajouter, donc la conversion est sûre.

```csharp
IEnumerable<Ennemi> ennemis = new List<Gobelin> { new Gobelin { Nom = "Grik" } };   // ✅
foreach (var e in ennemis)
    Console.WriteLine(e.Nom);   // Grik
```

> [!NOTE]
> C’est l’équivalent C# des « wildcards » de Java (`List<? extends Ennemi>`). Le mot-clé `out` sur un paramètre de type (`interface IProducteur<out T>`) indique la covariance, `in` indique la contravariance.

## Dans Unity

Les génériques sont partout dans l’API Unity :

```csharp
var corps = GetComponent<Rigidbody>();                 // pas de cast, type vérifié
var cibles = GetComponentsInChildren<IDamageable>();    // fonctionne aussi avec des interfaces
var balle = Instantiate(prefabBalle);                   // Instantiate<T> renvoie le même type que le prefab
```

Et on peut en écrire soi-même, par exemple une base de [pool d’objets](<../../Chapitre 2/Partie IV — Patterns complémentaires/14. Object Pool.md>) :

```csharp
public abstract class Pool<T> : MonoBehaviour where T : Component
{
    [SerializeField] private T prefab;
    // …
}

public class PoolDeBalles : Pool<Balle> { }   // ✅ classe concrète, attachable à un GameObject
```

> [!WARNING]
> **Unity ne peut pas attacher un composant générique ouvert.** `Pool<T>` ne peut pas être ajouté à un GameObject : il faut une sous-classe **non générique** (`PoolDeBalles : Pool<Balle>`). En revanche, Unity sait sérialiser dans l’Inspector un champ d’un type générique fermé, comme `List<int>` ou une classe `[Serializable]` `Paire<int, string>` (Unity 2020.1+).

---

## ⚠️ Pièges courants

* **Rendre générique ce qui ne l’est pas.** Si une seule implémentation existe et qu’aucune autre n’est prévue, un type concret est plus simple à lire.
* **Oublier la contrainte** puis caster `T` vers un type précis à l’intérieur de la méthode : c’est le signe qu’il manquait un `where`.
* **Comparer deux `T` avec `==`** : sans contrainte, ça ne compile pas. Utiliser `EqualityComparer<T>.Default.Equals(a, b)` ou une contrainte d’interface.

## 🔀 À ne pas confondre

* **Générique** (un même code, plusieurs types, vérifié à la compilation) et **`object`** (n’importe quoi, vérifié à l’exécution).
* **Polymorphisme par héritage** (choisi à l’exécution selon le type réel de l’objet) et **polymorphisme paramétrique** (fixé à la compilation par le paramètre de type).

## 🧪 Exercice : le meilleur combattant

1. Écris une classe abstraite `Combattant` qui implémente `IComparable<Combattant>`, avec un `Nom` et une propriété abstraite `Puissance`. Deux combattants se comparent par leur puissance. `ToString()` renvoie `"Nom (Puissance)"`.
2. Crée `Guerrier` (puissance = force × 2) et `Mage` (puissance = magie × 3).
3. Écris une méthode générique `MeilleurDe<T>(IEnumerable<T> candidats)` qui renvoie le plus grand élément. Elle doit fonctionner pour des combattants, des entiers ou des chaînes, et lever une `ArgumentException` si la liste est vide.

**Contrainte :** pas de LINQ (`Max`, `OrderBy`…) dans `MeilleurDe`.

**Test attendu :**

```csharp
var equipe = new List<Combattant>
{
    new Guerrier("Conan", 20),
    new Mage("Merlin", 15),
    new Guerrier("Xena", 18)
};

Console.WriteLine(MeilleurDe(equipe));
Console.WriteLine(MeilleurDe(new[] { 4, 9, 2 }));
Console.WriteLine(MeilleurDe(new[] { "pomme", "kiwi", "banane" }));
```

```
Merlin (45)
9
pomme
```

<details>
<summary>Voir la solution</summary>

```csharp
public abstract class Combattant : IComparable<Combattant>
{
    public string Nom { get; }
    public abstract int Puissance { get; }

    protected Combattant(string nom) => Nom = nom;

    public int CompareTo(Combattant autre) => Puissance.CompareTo(autre.Puissance);

    public override string ToString() => $"{Nom} ({Puissance})";
}

public class Guerrier : Combattant
{
    private readonly int force;
    public Guerrier(string nom, int force) : base(nom) => this.force = force;
    public override int Puissance => force * 2;
}

public class Mage : Combattant
{
    private readonly int magie;
    public Mage(string nom, int magie) : base(nom) => this.magie = magie;
    public override int Puissance => magie * 3;
}

public static T MeilleurDe<T>(IEnumerable<T> candidats) where T : IComparable<T>
{
    T meilleur = default;
    bool premier = true;

    foreach (T candidat in candidats)
    {
        if (premier || candidat.CompareTo(meilleur) > 0)
        {
            meilleur = candidat;
            premier = false;
        }
    }

    if (premier)
        throw new ArgumentException("La liste de candidats est vide.", nameof(candidats));

    return meilleur;
}
```

</details>

| Élément | Syntaxe |
