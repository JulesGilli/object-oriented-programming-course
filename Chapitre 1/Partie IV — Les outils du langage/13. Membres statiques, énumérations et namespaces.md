## Membres d’instance et membres statiques

Un membre **d’instance** appartient à **chaque objet** : chaque astronaute a son propre nom. Un membre **statique** appartient à **la classe elle-même** : il existe en un seul exemplaire, partagé par tous les objets, et il existe même si aucun objet n’a été créé.

```csharp
public class Astronaute
{
    private static int prochainId = 1;          // partagé par toutes les instances

    public static int NombreCrees { get; private set; }

    public int Id { get; }                       // propre à chaque instance
    public string Nom { get; }

    public Astronaute(string nom)
    {
        Nom = nom;
        Id = prochainId++;
        NombreCrees++;
        Console.WriteLine($"{Nom} embarque ! (#{Id})");
    }
}
```

```csharp
var a1 = new Astronaute("Thomas");
var a2 = new Astronaute("Sophie");
Console.WriteLine($"Astronautes créés : {Astronaute.NombreCrees}");
```

**Sortie :**

```
Thomas embarque ! (#1)
Sophie embarque ! (#2)
Astronautes créés : 2
```

On accède à un membre statique **par le nom de la classe** (`Astronaute.NombreCrees`), jamais par un objet.

> [!NOTE]
> Une méthode `static` n’a pas de `this` : elle ne peut pas accéder directement aux membres d’instance. C’est logique, puisqu’elle n’est attachée à aucun objet en particulier.

### Les classes statiques

Quand une classe ne contient **que** des membres statiques (des fonctions utilitaires, des constantes), on la déclare `static` : elle ne peut alors ni être instanciée, ni servir de classe de base. `Math`, `Console` ou `File` sont des classes statiques.

```csharp
public static class Combat
{
    public static int Borner(int valeur, int min, int max)
        => Math.Clamp(valeur, min, max);
}

Console.WriteLine(Combat.Borner(150, 0, 100)); // 100
```

### Les méthodes d’extension

Une méthode statique d’une classe statique, dont le premier paramètre est précédé de `this`, peut être appelée **comme si elle appartenait au type étendu**. C’est ainsi que fonctionne LINQ (`liste.Where(...)`).

```csharp
public static class ExtensionsTexte
{
    public static string Crier(this string texte) => texte.ToUpper() + " !";
}

Console.WriteLine("attention".Crier()); // ATTENTION !
```

> [!WARNING]
> **`static` n’est pas un raccourci pour « accessible partout ».** Un champ `public static` modifiable est une **variable globale** déguisée : n’importe quel code peut le changer à n’importe quel moment, ce qui augmente le couplage et complique les tests (voir [9. Visibilité et portée](<../Partie III — Concepts Avancés/9. Visibilité et portée.md>)). Réserve `static` aux données vraiment partagées par toutes les instances et aux fonctions sans état.

## Les énumérations (`enum`)

Une `enum` définit un **ensemble fini de valeurs nommées**. C’est bien plus sûr qu’une `string` (« gobelin », « Gobelin », « gobelim »…) ou qu’un entier magique.

```csharp
public enum TypeEnnemi
{
    Gobelin,
    Orc,
    Dragon
}
```

Combinée à une expression `switch`, une enum rend le code lisible et explicite :

```csharp
static int PointsDeVie(TypeEnnemi type) => type switch
{
    TypeEnnemi.Gobelin => 30,
    TypeEnnemi.Orc     => 80,
    TypeEnnemi.Dragon  => 500,
    _ => throw new ArgumentOutOfRangeException(nameof(type))
};

Console.WriteLine(PointsDeVie(TypeEnnemi.Orc)); // 80
Console.WriteLine((int)TypeEnnemi.Dragon);       // 2 : une enum est un entier nommé
Console.WriteLine(TypeEnnemi.Dragon);            // Dragon
```

> [!TIP]
> Un `switch` sur une enum qui grossit à chaque nouveau type est un signal : le comportement devrait peut-être vivre dans des classes polymorphes (principe ouvert/fermé, voir [11. Principes SOLID](<../Partie III — Concepts Avancés/11. Principes SOLID.md>)). Les enums sont parfaites pour des **étiquettes** ; elles le sont moins pour porter beaucoup de **comportement**.

### Combiner des options avec `[Flags]`

Quand plusieurs valeurs peuvent être actives **en même temps**, on utilise des puissances de 2 et l’attribut `[Flags]` :

```csharp
[Flags]
public enum Element
{
    Aucun  = 0,
    Feu    = 1,
    Glace  = 2,
    Poison = 4
}
```

```csharp
Element attaque = Element.Feu | Element.Poison;   // combine deux options
Console.WriteLine(attaque);                       // Feu, Poison
Console.WriteLine(attaque.HasFlag(Element.Glace)); // False
```

## Les namespaces

Un **namespace** (espace de noms) regroupe des types et évite les conflits de noms. Deux classes peuvent porter le même nom si elles sont dans des namespaces différents :

```csharp
namespace Chocolat
{
    public class Mars
    {
        public string Decrire() => "Une barre chocolatée.";
    }
}

namespace Planete
{
    public class Mars
    {
        public string Decrire() => "La quatrième planète du système solaire.";
    }
}
```

Pour les utiliser ensemble, on peut écrire le **nom complet**, ou créer un **alias** avec `using` :

```csharp
using PlaneteMars = Planete.Mars;

var friandise = new Chocolat.Mars();
var planete = new PlaneteMars();
Console.WriteLine(friandise.Decrire()); // Une barre chocolatée.
Console.WriteLine(planete.Decrire());   // La quatrième planète du système solaire.
```

Bonnes pratiques :

* calquer les namespaces sur les dossiers du projet (`MonJeu.Combat`, `MonJeu.UI`, `MonJeu.Sauvegarde`) ;
* depuis C# 10, préférer la forme courte `namespace MonJeu.Combat;` en tête de fichier, qui évite un niveau d’indentation.

## Dans Unity

* **Enums dans l’Inspector :** un champ `[SerializeField] private TypeEnnemi type;` s’affiche sous forme de **liste déroulante**. Une enum `[Flags]` s’affiche comme une liste à cases multiples.
* **Champs statiques et Inspector :** les champs `static` ne sont **ni sérialisés ni affichés** dans l’Inspector. Leurs valeurs ne sont pas sauvegardées avec la scène.
* **Champs statiques et Play Mode :** si le *Domain Reload* est désactivé (*Enter Play Mode Options*), les champs statiques **gardent leur valeur** d’une session de jeu à l’autre. Un compteur comme `prochainId` ne repartirait pas à 1. Il faut alors le réinitialiser avec une méthode marquée `[RuntimeInitializeOnLoadMethod]`.
* **Événements statiques :** un `public static event Action OnPartieTerminee;` est pratique, mais tout abonné doit se désabonner, sinon il reste référencé jusqu’à la fermeture de l’application.
* **Namespaces :** Unity n’impose rien, mais placer ses scripts dans des namespaces évite les conflits avec les packages et les assets du Store (beaucoup définissent leur propre `GameManager` ou `Player`).

## ⚠️ Pièges courants

* **Mettre un état de partie dans un champ statique** (score, PV du joueur) : il survit aux changements de scène et aux relances, et devient très difficile à réinitialiser proprement.
* **Changer l’ordre des valeurs d’une enum** utilisée dans des données sauvegardées ou sérialisées : Unity enregistre la **valeur entière**. Insérer `Troll` entre `Gobelin` et `Orc` transforme silencieusement tous les orcs existants en trolls. Ajoute les nouvelles valeurs **à la fin**, ou fixe les valeurs explicitement (`Orc = 1`).
* **Oublier `[Flags]` et les puissances de 2** : `Feu | Glace` n’a alors aucun sens.

## 🔀 À ne pas confondre

* **`static`** (un exemplaire par classe) et **`const`** / **`readonly`** (une valeur qui ne change pas). Un champ `static` peut être modifiable ; un `const` est implicitement statique et fixé à la compilation.
* **Classe statique** et **Singleton** : la classe statique n’a pas d’instance du tout (pas d’interface, pas de polymorphisme, pas d’injection possible) ; le [Singleton](<../../Chapitre 2/Partie I — Patterns Créationnels/1. Singleton.md>) est un objet unique, qui peut implémenter une interface.

## 🧪 Exercice

Écris une classe `Ennemi` qui :

* reçoit un `TypeEnnemi` dans son constructeur ;
* expose une propriété `PointsDeVie` calculée selon le type (Gobelin 30, Orc 80, Dragon 500) ;
* tient à jour, **pour chaque type**, le nombre d’ennemis créés, consultable avec une méthode statique `Ennemi.NombreDe(TypeEnnemi type)`.

**Contrainte :** pas de `if`, et un seul champ statique.

**Test attendu :**

```csharp
var ennemis = new List<Ennemi>
{
    new(TypeEnnemi.Gobelin), new(TypeEnnemi.Gobelin),
    new(TypeEnnemi.Orc), new(TypeEnnemi.Gobelin)
};

foreach (TypeEnnemi type in Enum.GetValues<TypeEnnemi>())
    Console.WriteLine($"{type} : {Ennemi.NombreDe(type)}");

Console.WriteLine($"PV totaux : {ennemis.Sum(e => e.PointsDeVie)}");
```

```
Gobelin : 3
Orc : 1
Dragon : 0
PV totaux : 170
```

<details>
<summary>Voir la solution</summary>

```csharp
public class Ennemi
{
    private static readonly Dictionary<TypeEnnemi, int> compteurs = new();

    public TypeEnnemi Type { get; }

    public Ennemi(TypeEnnemi type)
    {
        Type = type;
        compteurs[type] = NombreDe(type) + 1;
    }

    public static int NombreDe(TypeEnnemi type)
        => compteurs.TryGetValue(type, out int nombre) ? nombre : 0;

    public int PointsDeVie => Type switch
    {
        TypeEnnemi.Gobelin => 30,
        TypeEnnemi.Orc     => 80,
        TypeEnnemi.Dragon  => 500,
        _ => throw new ArgumentOutOfRangeException()
    };
}
```

Le dictionnaire est `static` (partagé par tous les ennemis) et `readonly` (la référence ne change jamais, même si son contenu évolue).

</details>

## ✅ Récap

| Outil | Rôle | Exemple |
| --- | --- | --- |
| Membre `static` | Donnée ou fonction partagée par toute la classe | `Astronaute.NombreCrees` |
| Classe `static` | Regroupe des fonctions utilitaires sans état | `Math`, `Combat.Borner(...)` |
| Méthode d’extension | Ajoute une méthode « apparente » à un type existant | `"texte".Crier()` |
| `enum` | Ensemble fini de valeurs nommées | `TypeEnnemi.Orc` |
| `[Flags] enum` | Combinaison d’options | `Element.Feu \| Element.Poison` |
| `namespace` | Organise le code et évite les conflits de noms | `Chocolat.Mars` / `Planete.Mars` |
